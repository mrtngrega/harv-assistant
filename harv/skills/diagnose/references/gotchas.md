# Known traps on these computers

Traps already hit while building things on a Windows 11 PC and a Fedora (KDE Plasma) notebook. Check the ones that match before building a theory: each one has cost real hours once. When you hit a new one, add a line under its heading (symptom → cause → what works).

## Windows shells

- **Git Bash eats backslashes**: heredocs (even quoted `<<'EOF'`), `sed -i` replacements and `node -e '…'` strings can lose `\` or turn `\\n` into something else, so Windows paths and escapes silently change. The same goes for a Python edit script fed through a heredoc: a `\n` meant for the target file can land as a real line break inside a JS string. A `node -e "…"` in double quotes also loses its backticks: bash runs them as commands (template strings, SQL in backticks). → Write scripts to a file with the editor, or use forward slashes; check regexes and `\n` in the result.
- **Git Bash turns `/word` arguments into paths** (`/model` → `C:/Program Files/Git/model`). → `MSYS_NO_PATHCONV=1` before the command.
- **PowerShell 5.1**: no `&&`/`||` (use `; if ($?) { … }`), no `?:` or `??`; `2>&1` on a native program wraps stderr lines in errors and sets `$?` false even on exit code 0; `Set-Content` writes the ANSI code page (pass `-Encoding utf8`).
- **A process search finds itself**: `pgrep -f "<text>"` or a CIM query on `CommandLine -like '*text*'` matches the shell running the search, since its own command line contains the text. → `pgrep -x <name>`, or search from a script file.
- **Headless Chrome/Edge screenshots from Git Bash**: `--screenshot=…` from Git Bash wrote no file in two runs (2026-11-03); the same command from PowerShell worked. → Take browser screenshots from PowerShell (or with Playwright/CDP).
- **A skill's text is loaded once per Claude Code session**: after editing a skill, the Skill tool (and subagents started from that session) still get the old text. → Test an edited skill in a new session, or have the test read the SKILL.md file directly.
- **No new programs during a Windows shutdown**: a process started after `WM_QUERYENDSESSION` fails with 0xc0000142 ("unable to start correctly", an error popup in the event log as Application Popup 26). → Start what the shutdown needs beforehand and keep it waiting.
- **`FindWindowW` with a null class** from PowerShell needs `[NullString]::Value`, not `$null` (which becomes an empty string). Its title match ignores case and returns the first hit, hidden windows too ("Rewire" found a hidden helper window "rewire"). → Check `IsWindowVisible`, or enumerate the process's windows.
- **Grep tool on a single file fails** with `error parsing glob '!{**/.claude/.credentials.json'` (2026-11-21). → Give the folder as `path` and the file name as `glob`.
- **Tk window built while busy threads run is slow**: a Tkinter app whose input/output threads were already running took ~21 s to build its window (each Tk call waits for the GIL); built first, 0.6 s. → Build the window, then start the threads.
- **Python on Windows can't see Git Bash's `/tmp`** (it reads `/tmp/x` as `C:/tmp/x` or the user's Temp). → Pass Windows paths, or files inside the working folder.
- **At shutdown Windows closes console programs early**: a server started in a hidden console (`cmd.exe` / `Start-Process -WindowStyle Hidden`) gets CTRL_SHUTDOWN_EVENT, which Node can't catch, often before other apps hear `WM_QUERYENDSESSION`. → Anything that must happen at shutdown runs in the GUI app itself, not in the server.
- **Windows holds startup apps back** for ~20 s after login (Run-key entries): "starts with Windows" isn't instant. → Do the urgent part first in whatever starts, and measure from the login.

## Files and line endings

- **Python on Windows writes CRLF** in text mode (`open(p, 'w')`), flipping a whole LF file and making a huge diff. → Open in binary (`'wb'`, encode yourself) or edit with the editor tool.
- **An exact-text edit script stops matching a file it matched a minute ago**: `git stash` / `stash pop` / `checkout` rewrote the working file with CRLF (`core.autocrlf`), so `\n`-joined search text no longer occurs. → Read the file's line ending first and join the search and replacement text with it (or edit with the editor tool).
- **A shell command never returns, no output, until its timeout**: something in it reads stdin and waits for ever (a stray `cat > file` or `cat > /dev/null` with no input, `read`, a tool that prompts). → Give every such command input or `</dev/null`; when one hangs, look for the part that reads stdin.
- **Locked files**: on Windows a file another program has open can't be deleted or renamed (`EBUSY`, `EPERM`): an editor, a running exe, antivirus scanning it, a terminal sitting in that folder. → Find who holds it (Resource Monitor, `handle.exe`), or retry after the program closes.
- **A test that writes Windows paths on Linux** can leave files literally named `\tmp\…` in the repo. → Delete them by exact name from Python; globs miss them.

## Node, Vite and dev servers

- **Orphaned servers on Windows**: stopping a background `npm run dev` can leave `tsx`/`vite`/`node` children holding the ports, and new servers then hang silently. → `netstat -ano | grep -E ":(4317|4316)"` (or the project's ports) and kill those PIDs with their tree. Never kill the Claude Code process.
- **Vite misses a change on Windows** now and then (the browser keeps old code). → Restart Vite before doubting the fix.
- **Editing a non-component module** (`lib/*.ts`) makes Vite reload the whole page: it looks like a restart while the server kept running. Check the server's own log before concluding it restarted.
- **A flaky test under full-suite load** (passes alone, fails in the full run, e.g. a pseudo-terminal test). → Run it alone to tell flake from bug; fix the timing with a wait on the real condition, not a longer sleep.
- **A page check that imports an app module gets a second copy** (`import('/src/lib/x.ts')` from CDP): after an edit Vite serves the module as `x.ts?t=…`, and the plain URL is a fresh copy with its own empty state. → Import the URL the page itself loaded (`performance.getEntriesByType('resource')`, the `?t=` one), or reload the page first.
- **Old errors show up in a fresh CDP check**: attaching replays the page's earlier console messages, so a bug already fixed still "logs". → Reload the page, then read the logs.
- **A shared package exported with `export type *`** hides any function added to that file (TS1362 "cannot be used as a value"). → Change it to `export *` when the file gets a runtime value.
- **`npm install` refuses install scripts** of new packages (npm's allowScripts). → Review the package, then `npm install-scripts approve <pkg>`.
- **A prompt rule about tool order doesn't hold on a small model**: "before your first tool call, say what you'll do" was ignored by Haiku every time, in the system prompt, at the front of the message and at its end. → Something that must always happen goes in a hook (the gate sends the call back once), and is checked live on Haiku before calling it done.
- **`git count-objects -v` says 0 KiB on Windows** for a repo with only a few tiny loose objects (whole KiB, rounded down). → Don't test "size > 0" on a fresh repo.
- **A check's "bad sign" pattern matched its own all-clear line** (`/vertical shift/` in "no vertical shifts"). → Match the failure's own marker (`vertical shift:`) and run the check once on a clean state.

## Web views and desktop apps

- **`backdrop-filter` breaks `position: fixed`** inside it (the fixed element is placed relative to the blurred panel). → Render menus and popups in a portal at the body. A nested `backdrop-filter` inside another blurred panel doesn't blur at all. A popup inside a glass panel also can't rise above the next panel (the glass is its own layer): a list under the header went behind the history panel.
- **Tauri with several webviews**: the window is no longer a `WebviewWindow`; look the window and each webview up separately (`get_window`, `get_webview("main")`), or move/minimize/close stop working.
- **CDP screenshots of a Tauri/WebView2 app miss child webviews**: capture the screen (PrintWindow) to see what the user sees.
- **WebKitGTK (Linux Tauri) has no CDP**: drive the page in the same engine with Python GObject (`gi`, WebKit2 4.1 in an offscreen window; Harv has `scripts/ui-check/webkit-drive.py`, run with `GDK_BACKEND=x11` so it composites like the app), or take the real screen with `spectacle -b -n -f -o <file>`. Its `evaluate_javascript` doesn't wait for a promise; `call_async_javascript_function` does. Linux stacks a window's webviews in a vertical box unless they're moved into an overlay.
- **A closed child webview keeps its WebKitWebProcess on Linux** (Tauri multi-webview): `close()` doesn't free it, and removing or destroying the GTK widget doesn't either (WebKit keeps closed pages' processes for reuse; every closed tab stayed, ~170 MB each). → In `with_webview`, call `terminate_web_process()` (webkit2gtk feature `v2_34`), take it out of its container and destroy it, wait for that closure, then `close()`. Count `WebKitWebProcess` before and after to check.
- **`npm run app` (tauri build) can fail at the bundle step after building**, and a quick test then runs the old binary. → Check the build log for errors and the binary's time before testing.
- **WebKit and CSS columns**: a margin at a column break pushes the next column down, and a scrolling box (`overflow: auto`) inside columns is drawn in the wrong place (over the next section). → Space with padding, and nothing scrolls on its own inside columns. Chrome shows neither, so check Linux separately.
- **Tauri's `dragDropEnabled`** takes drops from the page: with it on, HTML5 drag and drop inside the page breaks on Windows. With several webviews (the `unstable` feature) the window takes OS file drops anyway, whatever the setting: the page sees no drag event at all (Windows still shows a copy cursor). → Handle Tauri's `DragDrop` window/webview event and hand the paths to the page.
- **Never wait on the main thread from inside a Windows callback** in a Tauri app (a drop, a window event): `webview.eval` or building a window from there deadlocks (the drop and the program dragging hang). → Do it from a spawned thread or an async command.
- **Text characters as icons** (× ‹ › ⟳ + ▾ ◍) come from different fonts on Windows and Linux and sit 1–1.5 px off their button's middle, more on Linux. → Drawn SVG icons, at even sizes in even-sized buttons (an odd size sits on half a pixel). Measure by pixels: `scripts/ui-check/centering.mjs`.
- **"Not centred in its row" can be the band, not the row**: every piece measured dead centre in its row, yet the row sat off-centre between its two divider lines because the strip had top padding and none below (2026-11-20). → Measure the gap from each divider to the content on both sides too (`scripts/ui-check/strip-align.mjs` does both), not just the pieces against their own box.
- **Two Tailwind classes for the same property on one element** (`h-5 h-6`, `text-faint text-warn`, `hidden flex`): which wins depends on the generated CSS order, not the class string, so an override "works" by luck. → Keep shared class strings layout-only and add colours per use; hide with a variant (`max-sm:hidden`) instead of `hidden` + `sm:flex` next to a shared `flex`.
- **A terminal window keeps popping up**: find who starts it by logging new processes with their parent (poll `Win32_Process`); a visible one shows as `OpenConsole.exe -Embedding` (Windows Terminal) next to it. A venv's `python.exe` started with no console (`DETACHED_PROCESS`) is only a launcher, and the real python under it opens a visible window. → Start `pythonw.exe` (no console, pipes still work), or a hidden console (`CREATE_NO_WINDOW` / Node's `windowsHide`).
- **Something that must happen at shutdown finds a helper process already gone**: Windows ends programs one by one by shutdown level, in no set order within one, and a windowless process is simply ended when its turn comes. A fake `WM_QUERYENDSESSION` sent to one window can't show this. → `SetProcessShutdownParameters`: the program that acts asks for 0x3FF (first), its helpers 0x100 (last). Proof is a real shutdown's log.
- **The Tauri app freezes when a command opens a window**: a synchronous `#[tauri::command]` runs on the main thread, and building a window there waits for that same thread (Windows). → Make the command `async`.
- **A Tauri window steals the focus when shown**, even built with `focusable(false)` / `focused(false)` (an overlay took the keyboard from the app being typed into). → On Windows add `WS_EX_NOACTIVATE` and show it with `ShowWindow(SW_SHOWNOACTIVATE)` + `SetWindowPos(HWND_TOPMOST, …SWP_NOACTIVATE)`; then hide it with `ShowWindow(SW_HIDE)` too, since Tauri's `hide()` does nothing for a window it never saw shown.
- **A window that isn't in any screenshot** may have `WDA_EXCLUDEFROMCAPTURE` (on purpose, like Harv's pill). → Check it with `EnumWindows` + `IsWindowVisible`/`GetWindowRect`, or its page over CDP, never a screen capture.
- **Coordinates off by the monitor's scaling** (a window "at 794" that is really at 992): the checking tool (PowerShell, a script) isn't DPI aware, so a monitor at 125% reports positions divided by 1.25. → Make the checker per-monitor aware (`SetProcessDpiAwarenessContext(-4)`) before calling it a bug.
- **React: `e.currentTarget` is null inside a state updater** (`setX((r) => … e.currentTarget …)` runs later, after the event). → Read what you need from the event first, then set state.
- **Checking Harv's pill from its own page lies after it hides**: the page keeps its last text when the app hides the window, and the app's `invoke` can't be wrapped to log calls. → Test the pure state (`pillState`, `nextChange`) and the window's visibility, not the page text.
- **A test through CDP or `SendInput` doesn't count as the user's input**: tools that watch for real mouse/keyboard use (Windows-MCP's takeover, idle detection) ignore it, so they behave differently when the user clicks for real. → Leave one real try to the user and say so.

## Fedora / Linux

- **`sudo` and polkit can't ask for a password over SSH** (`systemd-inhibit`, `sudo`, many `systemctl` system calls). → The session's own tools through the user bus (`kde-inhibit`, `systemctl --user`), or leave it to the user with the exact command.
- **SELinux denials** look like permission errors with correct file rights. → `ausearch -m avc -ts recent` / `journalctl -t setroubleshoot`.
- **SSH commands that start a long-running program hang** the SSH call. → `nohup … >log 2>&1 </dev/null &`.
- **Non-login SSH shells miss PATH entries** from `~/.bashrc` (user-installed Node, CLIs). → Export PATH in the command.
- **A Wi-Fi password kept in KWallet** (user-only connection) means no network until the user logs in: anything at boot can't reach the internet.
- **A command over SSH (or a child process) never returns after `wl-copy`**: wl-copy stays behind to serve the clipboard and keeps the caller's stdout/stderr open. → Run it with stdin/stdout/stderr to `/dev/null` (`subprocess.DEVNULL`).
- **A KWin script's `print()` shows up nowhere** you can read (not in `journalctl --user`). → Use the script only to act (raise a window); read state another way, e.g. `xprop -root _NET_CLIENT_LIST` + `xprop -id <id> _NET_WM_NAME` for X11 apps under Xwayland, or have the script `callDBus` back to a name you own (Harv's `linux_desktop.py` `KWin.run`/`windows()` does this).
- **A minimized app can't bring itself back on KDE Wayland once another app took input** (2026-11-25): GTK/Tauri `unminimize()` + `set_focus()` does nothing (focus-stealing prevention), yet works when nothing else was used meanwhile, so a quick demo passes. → Let a KWin script do it (`w.minimized = false; workspace.activeWindow = w`). Reproduce with real input in another app, not a demo.
- **Web push "sent" (Apple answers 201) but nothing shows on the phone**: the saved address can belong to an old device. A new iPhone restored from the old one keeps the Home Screen app but not its notification permission, and Apple keeps accepting pushes for the old address. → Ask whether the phone changed; turn notifications on again on the new phone.
- **Windows PowerShell 5.1 can't subscribe to WinRT events** ("cannot subscribe to Windows RT events"), so no BLE scanning or notifications there, and WinRT `IBuffer` values won't cast. → Use Python with `bleak` (in a venv); for unpairing, the `winrt` packages bleak brings (`device_information.pairing.unpair_async`).
- **A project folder can't be renamed from its own project chat**: the chat's process keeps it open ("being used by another process"). → Rename it from a normal chat (or after the project chat is closed), then reopen the project under the new name.
- **A check chained with `&&` went on although tests failed**: `npm test | grep …` takes grep's exit code, so a failing suite doesn't stop `&& git commit`. → Run the tests, read the result, then commit in a separate step (or `set -o pipefail`).
- **PowerShell variables ignore case**: `$t` and `$T` are the same variable, so a script that uses both silently overwrites one. → Give them different names.
- **A script's focus change is refused on Windows** (`SetForegroundWindow` or `AppActivate` reports success, the old window stays in front). → Press and release Alt with `keybd_event` first, then `SetForegroundWindow`. Launching an app also takes the focus: give it back to the window the user was in.
- **Testing whether a window is visible or in front, the setup lies easily**: a window exactly the size of its monitor (a maximized browser with a hidden taskbar) counts as full-screen, and another app maximized on the same monitor covers the window under test even when the focus is elsewhere. → Before trusting a result, print the foreground window, its rect and what `WindowFromPoint` returns at the spots that matter.
- **A Hugging Face download fails with "No such file or directory" on Windows** although the folder exists: the cache path (`models--org--name/snapshots/<40 hex>/<long file name>`) under a deep folder passes Windows' 260-character limit. → Point the cache at a short folder (`HF_HOME`, or the tool's own cache setting) close to the drive root or the home folder.
- **A Python helper that answers in JSON lines gets garbage instead of an answer**: a library it loads (model loaders, progress bars) prints to stdout. → Keep the real stdout for answers only (`ANSWERS = sys.stdout; sys.stdout = sys.stderr` at the start) and read stderr separately.
- **`getUserMedia` (the microphone) just hangs in a desktop app's web view, no error**: WebView2 shows its own permission prompt (unseen when the window is hidden), and WebKitGTK keeps media off and denies by default. → Grant the microphone in the app for its own page only (WebView2 `PermissionRequested`; WebKitGTK `enable-media-stream` + `permission-request`).
- **The gate holds `Remove-Item` on a path in a variable** ("can't see what it deletes"), and refuses a standalone `Start-Sleep` as a wait. → Use a fresh, timestamped folder instead of clearing an old one; wait with the desktop `Wait` tool or a `Monitor` until-loop.
- **An interactive CLI (`zeus create`/`zeus dev`, anything with inquirer prompts) dies with `ERR_USE_AFTER_CLOSE: readline was closed` in a background or Bash shell** (no stdin). → Run it with `terminal_run` and answer each prompt with a further `terminal_run`.
- **Clicking inside an emulator window (QEMU, the Garmin Connect simulator) makes it grab the mouse** and the pointer is stuck in it. → Ctrl+Alt+G releases it; send that right after any click or press inside the window.
- **A pywin32 call that doesn't exist fails silently inside a "never fail the main call" wrapper** (`win32gui.IsZoomed` isn't in pywin32: an `except Exception` around it hid the AttributeError and nothing moved). → Use `ctypes.windll.user32.<Name>` for what pywin32 lacks, and test such helpers by running them directly, not only through the wrapper.
- **Windows 11's Notepad (and other Store apps) hand the window to another process**: the pid you launched exits at once and owns no window. → Find the new window by "not there before the launch" plus the exe name or the title, not by the pid alone.
- **A scratch `.ts` script run with `npx tsx` fails on top-level await or on `import 'C:/…'`**: outside a `"type": "module"` folder tsx compiles to CommonJS, and Windows absolute paths aren't URLs. → Name it `.mts` and import repo files as `file:///C:/My%20files/…`.
- **A phone photo opened with Pillow is sideways or its coordinates do not match the picture you were shown**: phone photos store their rotation in EXIF (the file says 5712x4284, the viewer shows 4284x5712). → Apply `ImageOps.exif_transpose` before cropping or measuring; and when two photos are compared, measure gaps relative to a fixed part of the object (the watch glass edge) because the camera distance changes between shots.
- **A `sed` edit inside a TypeScript string broke the server: Prettier had turned the string single-quoted, and the new text had an apostrophe** ("note's"), so the file no longer parsed (2026-11-20). → Edit text inside code strings with the Edit tool, which shows the quotes; never `sed` into a string.
- **`python -I` ignores `PYTHONIOENCODING` and every other `PYTHON*` variable**, so a test printed Slovak as `�` though the tool was fine (2026-11-20). → Write the output to a UTF-8 file (`-o`), or set `sys.stdout.reconfigure(encoding="utf-8")` in the script.
- **A rebuilt Harv app (`npm run app`) changed nothing in the app the user runs**: on Windows they run the installed copy in `%LOCALAPPDATA%/Harv/harv.exe`, not `target/release/harv.exe`, and a running app locks its exe (2026-11-22: the installed one was 4 days old). → Close the app (`taskkill /IM harv.exe /F`; the server keeps running), build, run `bundle/nsis/Harv_*_x64-setup.exe /S`, check the installed exe's time, then start it again.
- **A CDP screenshot of the Harv app hangs, and its layout readings make no sense** (rows wider than the window): the app window is minimized, so its page has `innerHeight` 0 (2026-11-22). → Check `innerWidth`/`innerHeight` first; measure the same dashboard code headless at the app's width (`strip-align.mjs 1326`), or ask before restoring the window while the user works
- **Tailscale's owner check doesn't tell the user's own devices apart**: a device shared to the account shows under the same `UserID` as theirs (`officepc`, 2026-11-22). → Use an explicit list (Settings › Safety › My other computers), never the tailnet owner, to decide what is theirs
- **A Haiku yes/no judge stays flaky on a condition (6/7, then noisier after one more prompt line)**: at low effort it answers before weighing the facts. → Make its JSON fill the deciding facts first (`job`, `kept`, `removes_kept`) and derive `asked` from them; it went to 14/14 (2026-11-22)
- **`pkill -f "<text>"` kills its own Bash call (exit 144)** when that text also appears in the same command line (a Chrome started with `--user-data-dir=/tmp/x` and later `pkill -f user-data-dir=/tmp/x`, 2026-11-23). The gate also holds `pkill` as "stops running programs". → Ask once, then stop it by pid (`kill <pid>` from `pgrep`), or have a test script close its own browser through CDP `Browser.close`.
- **Desktop control on the notebook: clicks and drags did not reach Chrome while a Dolphin window was in front** (Gmail attach button and drag-and-drop of a file, 2026-11-23: the screen stayed the same, nothing opened). → After two misses with an identical snapshot, stop and hand the physical step to the user instead of trying a third time blind.
- **A web page in a hidden Linux app window measures 0×0** (WebKitGTK: the Harv app in the tray, 2026-11-24): nothing is laid out, so every element's `getBoundingClientRect()` is empty and a "visible elements" filter finds nothing, though `innerText` still has the words. → When `document.body` has no width, skip size checks and judge visibility by styles and `hidden`/`aria-hidden` only.
- **Tauri's `on_download` on Linux: downloads cancelled for good** (2026-11-24): every webview with the same data directory shares one WebKit context, each adds its own handler there, WebKit asks only the first, and once that webview is closed Tauri answers false and wry cancels. WebKit 2.54 also never emitted decide-destination to a handler connected in download-started. → Watch the context once yourself (`connect_download_started`, then `created-destination`/`finished`/`failed`) and let WebKit name the file.
- **A model calls a deferred MCP tool with guessed inputs** (Haiku: `{"element":"1"}`, then `{"ref":"1"}`, two failed calls per browser click, 2026-11-24): tool search hides the schema until loaded, and the model skips loading it for a follow-up tool. → Name the exact inputs in the result that leads to that tool (the snapshot header), or `alwaysLoad` the tool if it is worth its prompt cost.
- **`adb shell cmd | tr/grep` or `grep -E 'a|b'` hangs or fails with "MemTotal: not found"** (2026-11-26): an unquoted `|` inside the adb command runs on the device as a pipe, so a second `grep` there waits for input. → Quote the whole remote command (`adb shell "grep -E 'A|B' /proc/meminfo"`), and pipe only after adb on the host. Fetch a long list once (`pm list packages`) instead of one adb call per item.

## Harv's safety gate

- The gate holds a whole chained command when one part needs a yes (e.g. stopping a process at the end of `edit && commit && push; kill`), and the yes means re-running it unchanged. So give a held-prone action its own call, and make scripted edits idempotent: a Python `s.replace(old, new)` where `new` starts with `old` adds the text again on every run (2026-11-25: a CLAUDE.md sentence doubled).
